# Демонстрация AI Sales Assistant за 5–7 минут

[← README](../README.md) · [Быстрый запуск](instructions/quickstart.md) ·
[Проверки и ограничения](VERIFICATION.md)

Этот сценарий показывает путь менеджера: вопрос клиента → черновик ответа →
внутренняя подсказка → проверка и ручное копирование. Для показа интерфейса
можно обойтись без настоящей модели и аккаунта amoCRM. Компания КлиматДом,
товары и переписка в примерах вымышлены.

## 1. Подготовка до показа

1. Подготовьте Python 3.12 и `.venv` по [Quickstart](instructions/quickstart.md).
   Если `.env` уже существует, сохраните его: повторное копирование шаблона
   перезапишет локальные настройки.
2. Для показа без ключа сохраните код заглушки из раздела
   [Manual check without an LLM key](instructions/testing.md#manual-check-without-an-llm-key)
   в `/tmp/stub_llm.py`. Заглушка возвращает один заранее заданный ответ
   о покупке: она показывает связь компонентов, а не качество LLM.
3. Запустите два процесса из корня проекта в разных терминалах.

Терминал A — локальная заглушка:

```bash
.venv/bin/python -m uvicorn --app-dir /tmp stub_llm:app --host 127.0.0.1 --port 9100 --no-access-log
```

Терминал B — приложение, направленное на эту заглушку:

```bash
LLM_BASE_URL=http://127.0.0.1:9100/v1 LLM_MODEL=stub .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000>. Если в `.env` заданы `UI_BASIC_AUTH_*`,
используйте собственные учётные данные в окне входа браузера. Не помещайте
логин и пароль в адресную строку. На сервере вне localhost нужны
[настройки доступа](instructions/access.md) и HTTPS.

Терминал C — проверка готовности:

```bash
curl -s http://127.0.0.1:8000/health
```

Ожидается `status: ok`. В ответе видно, что используется модель `stub` и
загружены 10 товаров/услуг и 7 FAQ. Если порт занят, выберите другой и
подставьте тот же адрес в браузере и командах.

## 2. Покажите вопрос и два блока ответа — 2 минуты

В поле сообщения вставьте:

```text
Сколько стоит Бриз 09 с установкой?
```

Нажмите **«Сгенерировать рекомендации»**. Объясните три элемента:

| Элемент | Что показать |
| --- | --- |
| Ответ клиенту | Черновик: «Бриз 09» — 42 900 ₽, стандартный монтаж — 9 900 ₽. Эти значения взяты из `data/knowledge_base.json` |
| Подсказка менеджеру | Отдельный внутренний блок с Wi-Fi модулем за 3 500 ₽ и фразой для предложения |
| Источники | Список позиций базы знаний, переданных модели, и технические детали запроса |

Сравните суммы с [базой знаний](../data/knowledge_base.json).
Измените приветствие в черновике и нажмите **«Копировать»**. Текст попадает
в буфер обмена. Менеджер сам решает, что вставить в чат и отправить.
Копировать внутреннюю подсказку клиенту целиком не следует.

## 3. Покажите, как проверяется качество — 1–2 минуты

В терминале C выполните автономную оценку поиска:

```bash
.venv/bin/python scripts/run_evals.py retrieval
```

В текущем проверенном наборе 24 вымышленных вопроса. Итог `PASS` означает,
что поиск прошёл фиксированные пороги `hit@1` и `recall`; результат
последнего прогона — в [отчёте](VERIFICATION.md). Эта команда не вызывает LLM.

Затем покажите полный набор тестов:

```bash
.venv/bin/python -m pytest
```

Тесты используют `FakeLLM` и `httpx.MockTransport`. В частности, они
проверяют жалобы, prompt injection, неизвестный товар, выдуманные суммы,
неверные JWT и превышение лимита. Заранее заданный ответ заглушки не
подходит для демонстрации качества ответов на все четыре кнопки UI.

## 4. Объясните границы результата — 1 минута

| Проверено локально | Требует отдельной проверки |
| --- | --- |
| Автотесты, оценка поиска, линтер, типы и ссылки документации | Качество ответов настоящей LLM |
| Интерфейс и HTTP-путь с заглушкой в ранее записанных прогонах | Полная интеграция с настоящим аккаунтом amoCRM |
| Настройка workflow GitHub Actions и его команды на локальной машине | Итог удалённого запуска GitHub Actions |

Настоящий виджет требует настройки интеграции, токенов и вебхуков по
[amoCRM integration](instructions/amocrm.md). Не представляйте показ
ручного интерфейса как проверку реального аккаунта amoCRM.

Для оценки настоящей модели есть отдельные
[сценарии диалогов](instructions/evaluations.md). Они запускаются явно,
требуют настроенного провайдера и могут расходовать его квоту.

## 5. Завершение

Остановите оба процесса сочетанием `Ctrl+C` в терминалах A и B.
Повторный показ использует те же вымышленные данные и не создаёт записей
в amoCRM. Порядок проверок и устройство CI описаны в
[CI/CD](CI_CD.md), краткие рабочие инструкции — в
[оглавлении README](../README.md#documentation).
