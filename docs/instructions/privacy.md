# Персональные данные: где они проходят и сколько хранятся

[← README](../../README.md) · [All documentation](../../README.md#documentation) · [Access protection](access.md) · [Резервное копирование](backup.md) · [Windows](windows.md)

У сервиса нет базы данных: он не хранит переписку, ответы модели и данные
клиентов на диске. Персональные данные проходят через него транзитом, а в
памяти процесса временно лежат только сообщения из вебхуков amoCRM. Ниже —
куда именно попадают данные клиента, что маскируется и как удалить то, что
сервис помнит.

Подробное объяснение механизмов — в руководствах этапов
[03](../STAGE_03.md#4-шаг-1-нормализация-входа),
[04](../STAGE_04.md#8-логи-без-персональных-данных) и
[06](../STAGE_06.md#5-вебхуки-и-кэш-сообщений).

## Где проходят данные клиента

| Где | Что там | Срок | Защита |
| --- | --- | --- | --- |
| Запрос к `/api/v1/suggest` | Сообщение, история, имя клиента | Только на время запроса | Вход менеджера (`UI_BASIC_AUTH_*`), лимит генераций |
| Провайдер LLM | Сообщение и история **после маскирования**, имя клиента, факты базы знаний | По политике провайдера | `REDACT_PII_FOR_LLM=true`: телефоны, e-mail и номера карт заменяются на `[телефон]`, `[email]`, `[номер карты]` |
| Кэш сообщений amoCRM (память процесса) | Тексты входящих и исходящих сообщений из вебхуков, ID сделки, контакта, беседы | До `AMOCRM_MESSAGE_TTL_HOURS` (24 ч) и не больше `AMOCRM_HISTORY_LIMIT + 10` сообщений на сделку и на контакт; пусто после перезапуска | Секрет вебхука; доступ только через JWT виджета |
| Данные контакта из REST API amoCRM | Полная запись контакта приходит в память сервиса на время запроса | Только на время запроса | В модель передаётся **только имя**; телефоны и e-mail контакта не используются |
| Счётчики лимита (память процесса) | Ключи `ip:<адрес>` и `amocrm:<аккаунт>:<пользователь>` с временем запросов | Окно 60 с; не больше 10 000 ключей; пусто после перезапуска | Не пишутся в лог |
| Логи | ID запроса, источник, ID позиций базы знаний, счётчики, коды ошибок | Как настроено на сервере | Тексты, имена, телефоны, IP и секреты не пишутся; фильтр маскирует их, если попадут случайно |
| Ответ ошибки валидации | Только имена полей | — | Значения полей не возвращаются |
| Отчёты оценок `reports/evals/` | Ответы модели на **вымышленные** сценарии | Пока не удалите | Папка в `.gitignore`; реальные диалоги в наборы не добавляются |
| Браузер менеджера | Сгенерированный ответ на странице | Пока открыта страница | Интерфейс ничего не сохраняет в `localStorage` |

## Что именно маскируется перед моделью

```text
redact_pii("Звоните +7 (916) 123-45-67, почта anna@mail.ru. Бюджет 42 900 ₽")
→ "Звоните [телефон], почта [email]. Бюджет 42 900 ₽"
```

| Распознаётся | Не распознаётся |
| --- | --- |
| Телефоны с `+7` или `8` в начале: `+7 (916) 123-45-67`, `8 916 123 45 67` | Номера без кода страны (`916 123-45-67`), иностранные номера |
| E-mail | Адреса, паспортные данные, фамилии внутри текста |
| Номера карт из 16 цифр группами по 4 | Карты другой длины |

Нераспознанное уходит провайдеру как есть. Если это недопустимо, выбирайте
провайдера с подходящими условиями обработки данных или локальную модель
(Ollama — см. [Quickstart](quickstart.md#configure-the-llm)).

## Как удалить то, что помнит сервис

| Что | Как |
| --- | --- |
| Весь кэш сообщений и счётчики лимита | Перезапустить сервис: `docker compose restart assistant` |
| Держать сообщения меньше | Уменьшить `AMOCRM_MESSAGE_TTL_HOURS`; устаревшие сообщения отбрасываются при следующем чтении кэша по этой сделке, полностью — при перезапуске |
| Перестать принимать переписку в кэш, оставив виджет | Удалить вебхук в amoCRM (амоМаркет → WEB HOOKS), оставив `AMOCRM_ENABLED=true`; менеджер вставляет сообщение в виджет вручную. Ранее сохранённый кэш очистить перезапуском |
| Полностью выключить интеграцию amoCRM | Установить `AMOCRM_ENABLED=false` и перезапустить сервис: виджет и вебхуки ответят `503 amocrm_disabled`; остаётся отдельный интерфейс менеджера |
| Данные у провайдера LLM | Только по правилам провайдера: сервис не может удалить их сам |
| Данные в amoCRM | Средствами amoCRM: сервис их не хранит и не изменяет |

## Ограничения

- Устаревшие сообщения удаляются из кэша не по таймеру, а при чтении кэша
  этой сделки или при вытеснении; до этого они остаются в памяти процесса
  (но не на диске). Перезапуск гарантированно очищает всё.
- Имя клиента передаётся модели — оно нужно для обращения в ответе.
- Маскирование основано на регулярных выражениях и пропускает форматы из
  правой колонки таблицы выше.
- HTTP Basic передаёт пароль менеджера в каждом запросе: только через HTTPS
  ([Access protection](access.md)).

## Как это проверяется

| Тест | Что доказывает |
| --- | --- |
| `test_personal_data_is_masked_before_llm` | Телефон и e-mail из сообщения не попадают в промпт |
| `test_redact_pii_masks_contacts_but_keeps_prices`, `test_redact_pii_keeps_sentence_punctuation` | Маскирование не трогает цены и знаки препинания |
| `test_widget_suggest_builds_context_from_webhooks` | Телефон и фамилия контакта amoCRM не попадают в промпт |
| `test_personal_data_is_not_logged`, `test_secrets_and_prompt_are_not_logged` | В логах нет телефона, имени, текста сообщения и ключа |
| `test_validation_error_does_not_echo_input` | Ошибка валидации не возвращает присланные значения |

```bash
.venv/bin/python -m pytest -k "personal_data or redact_pii or not_logged or echo_input or builds_context" -v
```
